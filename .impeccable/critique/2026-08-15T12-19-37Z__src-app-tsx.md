## Priority Issues

- [P0] LoadingScreen gates every hard reload, unconditionally, with no skip. Why it matters: MIN_DISPLAY_MS (~1.8s) plus video-ready time runs on every reload with no sessionStorage first-visit check and no Escape/click-to-skip — for a CTF audience that shares direct links and refreshes often, this taxes the exact return visits the hero's "peak" is trying to reward. Fix: gate the full ritual to true first-visit only; add a skip affordance matching the modal's own Escape handling. Suggested command: /impeccable optimize

- [P1] Mobile silently drops stack + status info on every project row. Why it matters: ProjectsList.tsx's ProjectRow hides the stack-tag row and status-dot+year column entirely on mobile (!isMobile &&), and reveals them only via :hover on desktop — there's no tap equivalent, so on touch the data isn't progressively disclosed, it's just gone. These are the two fastest signals a CTF teammate or recruiter uses to judge credibility, on the device most likely used for a shared link. The detector independently flagged the same element's reveal mechanism (transition: max-height, an animated layout property) as a layout-transition performance warning — same code, two angles. Fix: give mobile a persistent compact treatment (a second always-visible chip line, or tap-to-expand) instead of hover-gating it away. Suggested command: /impeccable adapt

- [P2] No failure state on external images. Why it matters: ProjectDetail.tsx renders images from opengraph.githubassets.com with no onError fallback — a rate-limited or renamed repo produces a raw broken-image glyph in an otherwise pixel-disciplined system. Fix: swap to a mono-labeled placeholder panel ("[ IMAGE UNAVAILABLE ]") on error. Suggested command: /impeccable harden

- [P2] Nav links are icon-only with no accessible label. Why it matters: Nav.tsx's [00]-[04] links carry no text and no aria-label — first-time visitors must hover-and-guess, and screen readers get only the literal bracket glyph. Fails recognition-over-recall for first-timers and is a real gap for screen-reader users. Fix: add aria-label per link, keep the visual bracket treatment as-is. Suggested command: /impeccable clarify

- [P3] DESIGN.md and the shipped home page have drifted from each other in both directions. The page ignores DESIGN.md's own signature corner-bracket reticle device (not used anywhere on Hero/Work/Archive/About/Contact/Nav); meanwhile DESIGN.md's token set doesn't yet cover 7 literals actually in use (fluid clamp() endpoints on About/Contact/ProjectDetail, #666, two scanline-texture rgba opacities) — mostly legitimate reused patterns the extraction pass missed, not real inconsistency, per the false-positive read above. Fix: apply the reticle to one focal element (avatar or hero image) as documented; run a follow-up /impeccable document pass to close the token gap. Suggested command: /impeccable polish
